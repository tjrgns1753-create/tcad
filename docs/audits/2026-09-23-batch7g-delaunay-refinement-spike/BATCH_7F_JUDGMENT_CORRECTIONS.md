# Batch 7F judgment corrections (Batch 7G Phase 1, section 2)

Batch 7F's own `REPORT.md` (in chat, and the audit folder's `REPORT.md` pointer) is left
completely unmodified. This file is a standalone correction layered on top of it, per this
batch's own instruction not to edit Batch 7F's materials.

| Hypothesis | Batch 7F's verdict | Corrected verdict (this batch) | Why |
|---|---|---|---|
| Red-green refinement / mesh quality | `CONFIRMED_PRIMARY_CAUSE` | **`CONFIRMED_BAD_MESH_PRODUCER / EXACT_MECHANISM_UNRESOLVED`** | Batch 7F proved refine_mesh_near() is the geometric SOURCE of the NodeVolume-area defect (isolated by the raw-vs-refined and structured-vs-imported comparisons) but never determined WHICH specific geometric property (non-Delaunay edges? T-junctions? overlaps? holes?) of its output causes DevSim's NodeVolume computation to disagree with the true area. "Primary cause" overstated a mechanism that was never actually identified — Batch 7G exists specifically to identify it. |
| Junction-column finite-volume inventory | `CONFIRMED_PRIMARY_CAUSE` | **`CONFIRMED_CONTRIBUTING_CAUSE`** (unchanged in substance, relabeled) | The R1-R2 exact-match evidence (relative error 0.000000 at all 3 levels) is real and stands, but this mechanism only explains the SMALL, well-understood R1-vs-R2 difference at the single junction node/column -- it does not, by itself, explain the much larger (18.6%-62.3%) whole-mesh NodeVolume-vs-area error Batch 7F itself measured, which is dominated by the transition-ring defect, not the junction column. Downgraded from "primary" to "contributing" to avoid conflating two different-sized effects under one label. |
| DEVSIM 2D formulation / public model limitation | `CONFIRMED_CONTRIBUTING_CAUSE` (based on 1 case: `struct_L3_R1_node_fixed`) | **`UNRESOLVED`** | A single non-converging case on a geometrically clean mesh is suggestive but not sufficient evidence for a formulation-level claim -- no tolerance sweep, no repeat at other coarse levels/doping combinations, and no isolation of WHY (Newton divergence vs. genuine non-existence of the equilibrium solution at that resolution) was done. Batch 7G's own section 13 physics comparison re-observes this same case class under controlled conditions but does not add the missing isolation work either -- still open. |
| Depletion y-collapse artifact | `CONFIRMED_PRIMARY_CAUSE` (for depletion measurement) | **Unchanged as the primary cause of the DEPLETION MEASUREMENT discrepancy specifically -- but NOT reinterpreted as a cause of terminal-current non-convergence.** | Batch 7F's own report already scoped this to depletion-recovery-POSITION measurement, but the phrasing in the hypothesis table risked being read as explaining the broader non-convergence syndrome. Explicitly restated: the y-collapse artifact explains why the OLD depletion-recovery NUMBER moved with refinement; it says nothing about why terminal current itself fails to converge (that remains explained, to the extent it is explained at all, by the mesh-quality findings above). |
| Current height (H/2H) scaling | `EXCLUDED_BY_EVIDENCE` for scaling; unit label `EMPIRICAL_HEIGHT_SCALING_ONLY` | **Unchanged** | The H/2H ratio=2.0000 finding and the "no official public-API unit confirmation" caveat both stand exactly as reported; nothing in Batch 7G's own investigation bears on current normalization at all (out of this batch's scope), so no correction is warranted here -- restated for completeness of the correction table, not because anything was wrong. |

No other Batch 7F finding (NodeVolume/area growth trend, R1-shift/R2-shift byte-identity, contact
geometry preservation, capability spikes A/B) is corrected -- those stand as measured.
